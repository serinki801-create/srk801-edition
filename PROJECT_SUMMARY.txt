WHAT THIS IS
--------------------------------------------------------------------------
  A 64-bit Long Mode hobby OS (x86_64) with:
    - Multiboot2-compliant bootloader (spec-correct header, 80 bytes)
    - Identity paging (4-level, 2 MB pages, first 512 MB + on-demand maps)
    - GDT with kernel/user segments (0x08/0x10/0x1B/0x23) + TSS (0x28)
    - IDT with 256 interrupt gates (incl. DPL=3 syscall gate 0x80)
    - PIC remapped to vectors 0x20-0x2F
    - CPU exception handlers with register dump + KERNEL PANIC
    - PIT 100 Hz timer, PMM bitmap + kernel heap, cooperative scheduler
    - VFS + TAR initrd, ELF64 loader, Ring 3 userland, int 0x80 syscalls
    - Framebuffer graphics (VBE, double buffered) + 8x8 font
    - NX/XD page protection, stack protector, user-pointer sanitizer
    - macOS-style composite window manager (menu bar, dock, windows)
    - PS/2 keyboard + mouse drivers, VGA text mode (80x25)
    - Interactive shell: AI-OS> (20+ commands, incl. ls/cat/exec/gui/
      desktop/secinfo) + Arch macOS-like distro build script


STEP-BY-STEP SUMMARY
--------------------------------------------------------------------------

STEP 0 — Project Bootstrap
  - Created /home/abzal/hobby-os
  - Wrote boot.asm with Multiboot2 header
  - Wrote kernel.c with VGA welcome screen
  - Wrote linker.ld and Makefile
  - Built kernel.elf (45 KB ELF64 statically linked)

STEP 1 — Bootloader & Long Mode Transition
  - boot.asm: Multiboot2 header, 32-bit protected mode entry
  - A20 line enable (port 0x92)
  - CPUID detection (leaf 0x80000001, Long Mode bit EDX[29])
  - 4-level page tables: PML4 -> PDPT -> PDT (2 MB pages, identity map)
  - CR3 = PML4 physical address, CR4.PAE=1, IA32_EFER.LME=1, CR0.PG=1
  - Far jump to reload CS (64-bit code segment selector 0x08)
  - Stack: 16 KB in .bss, aligned to 16 bytes

STEP 2 — VGA & Kernel Infrastructure
  - vga.c/vga.h: VGA text buffer at 0xB8000
    * vga_init(), vga_clear(), vga_putchar(), vga_print()
    * Cursor tracking, backspace, newline, scroll
  - port.h: inb() / outb() via GCC inline asm (AT&T syntax)
  - kernel.c: kmain() calls gdt_init(), idt_init(), keyboard_init(), vga_init()
    * Shell loop: waits for Enter, parses command, prints prompt
    * Commands: help, clear, echo <text>, info
    * HLT loop for power saving between keystrokes

STEP 3 — GDT (Global Descriptor Table)
  - gdt.c/gdt.h: 40-byte GDT
    * [0x00] Null descriptor (8 bytes)
    * [0x08] 64-bit Code segment (L=1, G=1, exec/read)
    * [0x10] 64-bit Data segment (read/write)
    * [0x18] TSS descriptor (16 bytes, 64-bit available TSS)
  - TSS structure: RSP0 = stack_top (kernel stack for ring 0)
  - lgdt loads GDTR, ltr loads TSS selector (0x18)
  - gdt_flush.asm (NASM): reloads DS/ES/FS/GS/SS, far jump to reload CS
    * Far jump encoded as raw bytes (NASM 2.16 quirk in ELF64)

STEP 4 — IDT & PIC
  - idt.c/idt.h: 256-entry IDT (4096 bytes, 16-byte aligned)
    * idt_set_entry(): builds 64-bit interrupt gate descriptor
    * type_attr = 0x8E (P=1, DPL=00, Type=1110 interrupt gate)
    * idt_load(): lidt instruction
  - pic_remap(): ICW1-ICW4 for master (0x20/0x21) and slave (0xA0/0xA1)
    * Master base vector: 0x20, Slave base vector: 0x28
    * All IRQs masked initially (0xFF)
  - pic_unmask_irq(1): opens keyboard IRQ on master PIC
  - cli before setup, sti after setup
  - idt_init() loops 0..255:
    * Vectors 0x21 (keyboard): keyboard_irq_handler
    * Vectors 0x20-0x27, 0x28-0x2F: default_irq_handler (EOI)
    * Vectors 0-31, 48-255: default_exception_handler (HLT loop)

STEP 5 — ISR Stubs (isr.asm)
  - default_exception_handler: HLT infinite loop (CPU stops safely)
  - default_irq_handler: saves RAX, sends EOI to master+slave PIC,
    restores RAX, iretq

STEP 6 — Keyboard Driver
  - keyboard.c/keyboard.h: PS/2 scancode Set 1
    * scancode_to_ascii[128]: make codes -> ASCII (lowercase)
    * scancode_to_ascii_shift[128]: shift variants
    * State: shift_pressed, caps_lock, input_buffer[256], input_len
    * Special keys: Backspace (0x0E), Enter (0x1C), Space (0x39)
    * keyboard_init(), keyboard_handle_scancode(), keyboard_get_input()
    * keyboard_is_input_ready(), keyboard_clear_input()
  - keyboard_isr.asm (NASM): assembly ISR for IRQ1
    * Saves 15 GP registers, aligns stack to 16 bytes (ABI)
    * in al, 0x60 -> mov dil, al -> call keyboard_handle_scancode
    * out 0x20, 0x20 (EOI to master PIC)
    * Restores registers, iretq
    * .note.GNU-stack section to silence linker warning
  - Compiled with -mno-sse -mno-sse2 (ISR cannot use XMM registers)

STEP 7 — Shell & I/O Integration
  - kernel.c shell loop:
    * Prints "AI-OS> " prompt
    * Waits for keyboard_is_input_ready() flag
    * keyboard_get_input() copies buffer, keyboard_clear_input() resets
    * handle_command(): help, clear, echo, info, unknown
  - Custom cmd_eq() and cmd_starts_with() (no libc dependency)

STEP 8 — Build System Fixes
  - linker.ld: C-style // comments replaced with /* */
  - NASM path: using Flatpak SDK NASM 2.16.03
    /var/lib/flatpak/runtime/org.freedesktop.Sdk/x86_64/25.08/.../nasm
  - NASM 2.16 quirk: far jump in ELF64 mode uses raw bytes:
    db 0x48, 0xEA  ; REX.W + opcode
    dw 0x08        ; selector
    dd target      ; 32-bit absolute offset
  - gdt_flush.asm, isr.asm, boot.asm, keyboard_isr.asm: .note.GNU-stack added
  - Makefile:
    * SRC_ASM includes all .asm files
    * keyboard.o and vga.o compiled with -mno-sse -mno-sse2
    * ISO target guarded with xorriso check
    * run-kernel target: qemu-system-x86_64 -kernel kernel.elf


PHASE 3 — Exceptions, Timer, Memory, Tasks (steps 9-13)
--------------------------------------------------------------------------
  WHY: превратить «голое» ядро в систему с диагностикой сбоев, временем,
  памятью и многозадачностью. Без этого невозможны файлы, юзерленд и GUI.

  STEP 9 — Boot paging 2 MB -> 512 MB + kernel_end + VGA hex helpers
  - WHY: весь Phase 3-5 (куча 256 КБ, битмап PMM 32 КБ, стеки задач,
    initrd-модуль, user-программы @0x400000, user-куча @16 МБ) не влез бы
    в исходные 2 МБ identity-map.
  - HOW: boot.asm в enable_long_mode циклом заполняет PDT: 256 записей
    entry[i] = (i * 2MB) | Present | Writable | PS. linker.ld получил
    символ kernel_end (всё ниже него PMM считает занятым). Исправлена
    передача mb_info в RDI (mov edi вместо mov rdi — zero-extend 32 бит).
  - vga.c/h: vga_print_hex8/32/64, vga_print_u64/dec для дампов и meminfo.

  STEP 10 — Исключения CPU и Kernel Panic
  - exceptions.asm (NASM): 32 стаба exc_stub_0..31. Векторы С кодом ошибки
    CPU (8, 10-14, 17, 21, 29, 30) кладут только номер вектора, остальные —
    сначала dummy error 0, потом вектор. Единый вид стека:
    [vector][error][RIP][CS][RFLAGS]. exc_common сохраняет 15 GP-регистров
    и зовёт C-обработчик.
  - exceptions.c: имена #DE..#SX, дамп RAX..R15, RIP/CS/RFLAGS/RSP, CR2/CR3,
    Error Code белым по красному, затем panic(). exceptions_init()
    перекрывает векторы 0-31 поверх idt_init (cli/sti вокруг).
  - panic.c/h: panic(msg) — красный баннер KERNEL PANIC, cli, вечный hlt.
  - Shell: команда crash (деление на ноль -> #DE -> дамп -> panic).
  - Сборка: exceptions.asm линкуется как exceptions_asm.o (иначе конфликт
    имени с exceptions.c -> exceptions.o).

  STEP 11 — Системный таймер PIT 8254 @ 100 Гц
  - timer.c/h + timer_isr.asm: divisor = 1193180/100 = 11931, порты
    0x43 (команда 0x36, канал 0, режим 3) / 0x40 (младший/старший байт).
    IRQ0 -> вектор 0x20, pic_unmask_irq(0). Стаб сохраняет регистры,
    зовёт timer_tick() (только g_ticks++), шлёт EOI в master PIC, iretq.
  - API: timer_ticks(), uptime_ms() (тики*10 мс), sleep_ms() (hlt-цикл).
  - Shell: команда uptime (секунды + мс + тики).
  - timer.o компилируется с -mno-sse (контекст прерывания, XMM не
    сохраняются в стабах — то же для keyboard/vga/exceptions/panic).

  STEP 12 — PMM bitmap + kernel heap (first-fit)
  - pmm.c/h: битмап 32 КБ на 1 ГБ (262144 фрейма по 4 КБ). pmm_init парсит
    Multiboot2 tag 6 (mmap, type==1 — свободно), всё ниже kernel_end и
    фрейм 0 резервирует. Без mmap — fallback 64 МБ. pmm_alloc_block (первый
    свободный, пропуск 0), pmm_free_block, pmm_reserve_range (для initrd и
    userland — добавлено в Phase 4), статистика total/free/blocks.
  - kheap.c/h: статический пул 256 КБ, free-list first-fit: kmalloc с
    выравниванием на 8 и сплитом блоков, kfree с коалесингом соседей,
    валидация указателя (внутри пула + из цепочки + занят), cli/sti.
  - Shell: meminfo (PMM total/free/blocks + heap total/used/free),
    testmem (kmalloc 32/1024/5000, паттерн-тест, reuse-тест, PASS).

  STEP 13 — Кооперативная многозадачность (Round-Robin)
  - task.h: task_t, rsp ОБЯЗАТЕЛЬНО первое поле (offset 0 для switch.asm);
    PID, state (EMPTY/READY/RUNNING), name[32], stack bounds, counter.
  - process.c: пулы 8 задач и 8 стеков по 8 КБ (BSS). process_init (задача 0
    = main), task_create(entry, name): строит стартовый стек
    [task_exit][entry][r15..rbp] так, что первый RET прыгает в entry, а
    возврат из entry ведёт в task_exit (вечный hlt).
  - switch.asm: task_switch(old, new) — push rbp/rbx/r12-r15, [old]=rsp,
    rsp=[new], pop, ret. Сохраняются только callee-saved — достаточно, т.к.
    yield это обычный вызов (caller-saved компилятор считает убитыми).
  - scheduler.c: scheduler_init (main + demo worker1/worker2 со счётчиками),
    scheduler_yield (следующая READY/RUNNING по кругу, main-цикл зовёт её
    каждую итерацию). Вытеснения по таймеру НЕТ осознанно: preempt внутри
    IRQ требует отдельных стеков — кооперативная модель надёжна.
  - Shell: tasks (PID/STATE/NAME/counter/rsp + число активных).


PHASE 4 — Userland, VFS и графика (steps 14-20)
--------------------------------------------------------------------------
  WHY: перевести систему из «демо ядра» в архитектуру с пользовательским
  пространством, файлами и графикой — база под Phase 5 (безопасность,
  оконный менеджер).

  STEP 14 — Multiboot2-заголовок по спеке (найден и исправлен баг)
  - БЫЛО: arch=3 вместо 0, неверная длина, info-тег 20 байт (не кратен 8).
    GRUB обходит теги шагом (size+7)&~7=24 и сбивался — заголовок фактически
    был битым (ранний runtime не проверялся, QEMU тут нет).
  - СТАЛО: magic/arch/length/checksum, len=80 (кратно 8, в первых 8 КБ):
    info-request {4,6,8,2}, framebuffer 1024x768x32, module-align, END
    (+4 паддинга внутри fb-тега, footprint 24). Проверено побайтово
    питон-скриптом: сумма 0, обход [(1,24),(5,20),(6,8),(0,8)].

  STEP 15 — GDT user-сегменты + IDT DPL-гейт
  - gdt.c/h: классический порядок null/kcode(0x08)/kdata(0x10)/
    ucode(0x18->0x1B, access 0xFA)/udata(0x20->0x23, access 0xF2)/
    TSS(0x28, был 0x18!). GDT_SIZE 40 -> 56. gdt_set/get_tss_rsp0()
    (переключение RSP0 на syscall-стек при exec). gdt_flush.asm: load_tss
    обновлён на 0x28.
  - idt.h/c: idt_set_entry_dpl(vec, addr, dpl), IDT_SYSCALL_VECTOR 0x80.

  STEP 16 — VFS + Initrd TAR
  - vfs.h/c: vfs_node_t {name, type, size, data, read/write/open/close/
    readdir, next/child}, корень "/", vfs_add_child, vfs_open
    ("/a" и "a", спуск на 1 уровень), vfs_read, vfs_dir_count,
    vfs_create_memfile (узлы в kheap, данные in-place).
  - initrd.c/h: парсер ustar (имя@0, octal-размер@124, typeflag@156,
    пропуск каталогов/'5', срез "./" и "/", конец — нулевой блок, кап
    64 файла), модуль ищется в Multiboot2 tag 3 (первый модуль, проверка
    границ), его страницы резервируются в PMM. Без модуля — builtin
    hello.txt/readme.txt (ls/cat работают и под qemu -kernel).

  STEP 17 — Ring 3 и системные вызовы
  - ABI int 0x80 (64-bit): EAX=номер, RDI/RSI/RDX=аргументы, RAX=возврат.
    Номера: 0 print, 1 read (неблокирующее, из keyboard-буфера), 2 exit,
    3 alloc. Обёртки — static inline в syscall.h (только для userland,
    ядро собирается с -DKERNEL и их не видит).
  - user.asm: syscall_int80_handler (сохраняет 15 регистров, достаёт
    saved rax/rdi/rsi/rdx со стека по точным смещениям, зовёт диспетчер,
    кладёт возврат в слот saved-rax, iretq), syscall_entry для LSTAR
    (сохраняет user-RSP, переходит на syscall-стек 16 КБ, диспетчер,
    sysretq raw-bytes 48 0F 07), switch_to_user_raw (сохраняет kernel
    RSP/RBP, грузит DS/ES/FS/GS=0x23, куёт IRETQ-кадр SS/RSP/RFLAGS=0x202/
    CS=0x1B/RIP на exec-стеке, iretq), user_exit_to_kernel (cli, restore
    RSP, pop rbp, ret — возврат в точку вызова switch).
  - syscall.c: диспетчер + sys_do_*; MSR STAR/LSTAR/FMASK + EFER.SCE
    (с CPUID-проверкой 0x80000001:EDX[11]); TSS.RSP0 переключается на
    syscall-стек на время exec и восстанавливается после; после возврата
    сегменты перезагружаются на 0x10. Вход в Ring 3 — через IRETQ (без
    ограничений STAR-раскладки), int 0x80 — основной ABI, SYSCALL-путь
    запрограммирован и ведёт в тот же диспетчер.
  - 64-битный нюанс: TSS в Long Mode не имеет полей SS — обработчики
    прерываний из Ring 3 работают с SS=0x23, это легально при CPL=0.

  STEP 18 — ELF64-загрузчик
  - elf.c/h: проверка магии/class/LE/x86-64/ET_EXEC-or-DYN, кап 16 phdr,
    предвалидация ВСЕХ PT_LOAD до копирования: vaddr в [0x400000, 512MB),
    вне [0x100000, kernel_end), offset+filesz внутри файла. Копирование
    filesz + обнуление BSS-хвоста (memsz). Возвращает entry (проверен
    диапазоном). user_prog линкуется на 0x400000 (user/user.ld, ET_EXEC).

  STEP 19 — Framebuffer и графика
  - framebuffer.c/h: парсинг MB2 tag 8 (только packed RGB type==1,
    bpp 16/24/32, кап 4096x4096). Если буфер выше identity-map (адреса QEMU
    ~0xE0000000) — fb_map_range() домэппивает 2-МБ страницами через свою
    PDT в BSS: PDPT находится через CR3->PML4[0] (без правок boot.asm),
    затем reload CR3 (сброс TLB).
  - Рисование в back-буфер 3 МБ (1024x768x32, NOBITS): put_pixel (32/24/BGR,
    16/RGB565), fill_rect, draw_char/draw_string шрифтом 8x8
    (font.h: 96 глифов 0x20-0x7F, MSB = левый пиксель), fb_flip() построчно
    с учётом pitch — двойная буферизация, ни одного тиаринга.
  - Без тега (qemu -kernel, текстовый VGA): fb_available()==0, gui/desktop
    честно сообщают об этом.

  STEP 20 — Userland-программа, initrd-образ, GRUB, shell
  - user/user_prog.c: freestanding без libc, main() тестирует sys_alloc +
    паттерн, опрашивает sys_read, sys_exit(42). user_start.asm: _start ->
    call main -> sys_exit(rax). user.ld: ENTRY _start, база 0x400000,
    /DISCARD/ для note/eh_frame. user_prog.elf: ET_EXEC x86-64, PT_LOAD на
    0x400000/0x401000 (проверено readelf).
  - Makefile: USER_CFLAGS/USER_LDFLAGS, цели userprog/initrd, initrd.img
    собирается tar --format=ustar (hello.txt, readme.txt, user_prog.elf),
    ISO кладёт kernel.elf + initrd.img, grub.cfg: gfxmode 1024x768x32,
    gfxpayload=keep, module2 /boot/initrd.img. run-цели с -vga std
    (важно для framebuffer), run-module для -kernel + -initrd без ISO.
  - kernel.c: init-порядок vga,gdt,idt,exceptions,timer,pmm,kheap,scheduler,
    keyboard,vfs,initrd,syscall,fb. Команды ls (с числом TAR-файлов),
    cat <file> (кап 8 КБ + [truncated]), exec <prog> (elf_load ->
    switch_to_user_mode на 16-КБ user-стеке в BSS -> код выхода),
    gui (демо: фон, окно, палитра, живые часы, эхо ввода, выход по
    exit/ESC; после выхода текстовая консоль невидима до ребута —
    на FB остаётся предупреждение).


PHASE 5 — Безопасность, macOS-стол, Arch-дистрибутив (steps 21-25)
--------------------------------------------------------------------------
  WHY: закрыть дыры, найденные аудитом Phase 4; дать графике оконный
  менеджер вместо статичной картинки; упаковать «macOS-опыт» для хоста
  (Arch ISO + Docker-OSX) — и честно зафиксировать, где проходит граница
  между темой оформления и настоящим macOS/Xcode.

  STEP 21 — Аудит безопасности и защита памяти (security.c/h)
  - НАЙДЕННЫЕ ДЫРЫ И ФИКСЫ:
    a) sys_alloc раздавал блоки KHEAP с inline-заголовками free-list в
       Ring 3: пользователь мог подделать заголовки и через kfree получить
       произвольную запись в памяти ядра. ФИКС: отдельная user-куча 1 МБ
       @16 МБ (вне ядра, внутри user-области, страницы NX, свой free-list
       first-fit в syscall.c, резерв в PMM). kheap ядра недосягаем.
    b) keyboard_get_input: underflow max_len-1 при max_len==0 (+NULL).
       ФИКС: гард в начале функции.
    c) sys_print/sys_read читали/писали по указателям Ring 3 без проверки
       (чтение/запись памяти ядра). ФИКС: security_check_user_ptr() —
       разрешены только [0x400000,512M) и окно текущего user-стека
       (ставится/сбрасывается в switch_to_user_mode); проверки NULL,
       переполнения addr+len, капа длины 1 МБ; отказ = лог [security]
       + возврат 0 (fail-closed).
    d) Весь код/данные исполняемы (2-МБ страницы без NX). ФИКС: EFER.NXE +
       сплит PDT[0..2] (0-6 МБ) в 4-КБ PT (3 статические таблицы в BSS):
       исполняем только [text_start, text_end) (символы добавлены в
       linker.ld), стеки/куча/BSS/низкая память — NX. Остальные 2-МБ
       страницы (6-512 МБ) помечены NX целиком; elf_load снимает NX
       постранично через security_set_exec() (4 запасные PT под on-demand
       сплит выше 6 МБ, отказ при исчерпании). Фреймбуфер мэппится с NX.
    e) Нет канареек стека (был -fno-stack-protector). ФИКС: Makefile
       переведён на -fstack-protector-strong (ядро и userland);
       рантайм свой (libc нет): security.c (__stack_chk_guard константа +
       __stack_chk_fail с красным баннером и halt), user/user_protect.c
       (fail -> sys_exit(134)). Ограничение задокументировано: без ASLR
       ключ фиксирован, ловит линейные переполнения.
  - Shell: secinfo (canary, политика NX, санитайзер, user heap, DPL=3/TSS).
  - security.o собирается с -mno-sse (вызовы из контекста прерываний).

  STEP 22 — Оконный менеджер в стиле macOS (wm.c/h, desktop.c, mouse.c/h)
  - WHY: gui из Phase 4 — статичная картинка; нужен композитный WM:
    несколько окон, фокус, перемещение, Dock с действиями.
  - mouse.c/h + mouse_isr.asm: PS/2 мышь с нуля — init с таймаутами
    (fail-soft: без мыши всё остальное работает), AUX enable (0xA8),
    compaq status (IRQ12+clock), команды 0xF6/0xF4 с ожиданием ACK,
    IRQ12 -> 0x2C, 3-байтные пакеты с ресинхронизацией по биту 3, EOI в
    slave+master PIC. API: mouse_x/y/buttons/present (кламп 1024x768).
  - wm.c/h: retained-модель (текст окон хранится, растр — при композите),
    z-order (фокусное рисуется последним), окна с тенью/рамкой/title bar/

KNOWN LIMITATIONS / HONEST NOTES
--------------------------------------------------------------------------
  - QEMU/xorriso отсутствуют в этой песочнице: сборка и статические тесты
    зелёные, рантайм не гонялся. Кандидаты на проверку при первом запуске:
    drag мышью, часы desktop, sys_read из Ring 3, gui на реальном VBE.
  - Рабочий ABI юзерленда — int 0x80. SYSCALL/SYSRET запрограммированы
    (STAR/LSTAR/FMASK/SCE) и ведут в тот же диспетчер, но тестовый бинарник
    ходит через 0x80 (надёжный путь; SYSRET-раскладка STAR под 0x1B/0x23
    не даёт одновременно корректные CS и SS — поэтому вход через IRETQ).
  - Stack canary фиксированный (без ASLR нечего рандомизировать) — ловит
    линейные переполнения, не targeted-атаки. SMAP нет: Ring 3 видит всю
    identity-mapped память чтением/записью напрямую; защита — санитайзер
    указателей в syscalls + изолированная user-куча + NX.
  - Кооперативный планировщик: вытеснения по таймеру нет (осознанно).
  - После gui/desktop текстовая VGA-консоль невидима до ребута (видеорежим
    остаётся графическим) — на FB остаётся предупреждение.
  - user_prog.elf выше 6 МБ не тестировался (нужны spare-PT для NX-гранта,
    всего 4); штатный адрес 0x400000 — в сплит-зоне, работает напрямую.
  - Xcode/.ipa НЕ запускаются ни на AI-OS, ни на Linux: только macOS
    (Mac или Docker-OSX на Apple-железе + Apple ID + Developer-аккаунт)
    либо облачная сборка (EAS Build / Codemagic). WhiteSur/Plank — только
    внешний вид.
  - Хост-скрипты (setup_*, run_*, full_*) проверены только статически
    (bash -n в make check): Arch-машины здесь нет, рантайм не гонялся.
    Safari под Linux не существует — в full_macos_setup.sh ставится Firefox.
    Нативный .ipa из Способа B ставится на jailbreak/AltStore, но НЕ в
    App Store (туда только Xcode-archive, Способ A).
