AI-OS x86_64 — СТАТУС ПОД LINUX MINT 22.3 (Ubuntu x86_64)
============================================================
Дата: 03 окт 2026
Машина: Linux Mint 22.3, TCG QEMU (KVM доступен через privileged cgroup),
         cc/clang 13.3.0 / 18.1.3, NASM 2.16.03 (Flatpak SDK)

РАБОТАЕТ / ПРОВЕРЕНО
------------------------------------------------------------------------
1. Ядро загружается: Multiboot2/GRUB -> 32-bit protected mode -> paging
   -> Long mode. Исправлены boot/gdt_flush (REX.W ea -> retfq), security.c
   (pdpt->pdt для NX-split), ISR стабы переименованны в .text.
2. Kernel паник, triple fault, #GP, #UD при boot — больше НЕТ.
   VGA output (баннер AI-OS, "boot: pmm total=..."). Таймер 100 Гц: 908 IRQ
   за 20 сек с отсутствием исключений.
3. Stack protector -fstack-protector-strong, NX/XD нарисован, user sanitizer
   (DPL=3, TSS, ring3 изоляция) — всё активно (см. secinfo в shell).
4. Встроенный мини-компилятор (minicc.c) выражений в shell:
   команды cc / cxx / objc / swift / build / samples подымаются.
5. Хост-демо ObjC+GNUstep+BlocksRuntime (tools/host_demo.m) — собирается
   строго флагами из ТЗ: gnustep-config --objc-flags -fblocks ... -lobjc
   -lBlocksRuntime. Вспомогательный шим tools/include/objc/blocks_runtime.h.
6. Desктоп-пример glass-визуала: framebuffer.c (fb_fill_rect_alpha,
   fb_glass_rect, fb_fill_round_rect), wm.c (Dock, menu bar, bounce,
   magnification, lowfx), desktop.c (Terminal/Sysinfo/Finder окна).
7. make / make check / make clean — всё проходит (ALL CHECKS PASSED).
   initrd.img содержит user_prog.elf + samples/hello.* в TAR/ustar.

НЕ ХВАТАЕТ / ЧТО НУЖНО СДЕЛАТЬ
------------------------------------------------------------------------
- NASM не установлен в PATH на чистой Mint: нужен sudo apt install nasm
  (мы используем fallback на Flatpak SDK NASM — но только если он есть).
- QEMU на KVM-accelerator падает без root/apt qemu-system-x86; сейчас
  работает TCG (user-mode эмулятор), но это медленно (5-10 s на загрузку).
  Установи: sudo apt install qemu-system-x86 xorriso (проверь в /dev/kvm).
- ISO (ai-os.iso) собран с xorriso, который был вручную dpkg-sym ?
  Чтобы автоматизировать: sudo apt install xorriso + qemu-system-x86.
- Реальный .ipa (App Store) на Linux собрать нельзя без Apple Dev Center:
  1) Mint (этот хост): Theos (https://github.com/theos/theos) + cctools-port
     + rcodesign — собирает arm64 Mach-O и ad-hoc подписывает. AltStore
     может установить на 7-дневный аккаунт.
  2) Docker Mac (docker-osx, sickcodes/docker-osx) + Xcode — только на
     Intel Haswell/Broadwell с включённым VT-x, нужен Apple ID, 50 ГБ.
  3) Для публикации в App Store — xcodebuild + Transporter — только macOS.
- Swift на чистом Mint: нет нативного swiftc (только Ubuntu-пакет swift,
  который не язык). Реальный Swift берётся с swift.org (download Swift
  toolchain for Ubuntu 22.04/24.04) и требует много зависимостей.
- tools/host_demo.m использует OBJCFLAGS -fblocks -Itools/include
  -I$(gcc --print-file-name=include): всё работает без sudo.
- Нет SMP/выделения памяти по DTR в framebuffer: fb_flip копирует
  построчно, на weak-железе 1024x768 32bpp может давать 30 FPS.
  Для малого железа используй: wm_set_lowfx(1) (vk по команде fx).
- Interface.ai для .ipa всё ещё за пределами Linux: Mint может пока
  только собрать host-часть (setup_ios_toolchain.sh нужен Arch).

BUG'и, пойманные в этой сессии:
  1) cputype arm64 = 0x0100000C (ARM|ABI64), а не 0x01000007 (это x86_64!)

  3) stale .o в micropython (make не трекит смену флагов) -> жёсткая чистка build-minimal
  4) mpthreadport.c: APPLE-секция без <pthread.h> при THREAD=0 -> локальный патч
  5) LDFLAGS_ARCH unix-порта: gcc-синтаксис -Wl,-Map= на Darwin ld -> -Wl,-dead_strip
